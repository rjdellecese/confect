title: "Migrate to table handles"
description: "Update existing Confect handlers, middleware, and tests to use table handles instead of loading your application's full database schema."
---

The database reader and writer now take **table handles** rather than strings. This changes how you select a table, not how you define one or what you store in Convex. Existing document IDs, indexes, and function paths stay the same.

## Update server implementations

1. Import `FunctionImpl` and `MiddlewareImpl` from your generated `_generated/server` module. Keep importing `GroupImpl` from `@confect/server`.
2. Remove the first (database schema) argument from `FunctionImpl.make`, `GroupImpl.make`, `MiddlewareImpl.make`, `MiddlewareImpl.provides`, and `MiddlewareImpl.makeByFunctionType`. Remove the runtime schema import too. The generated builders carry the application model as a type.
3. In each handler, helper, or middleware that reads or writes documents, import its table handles directly from `_generated/tables/<name>`. Replace calls such as `reader.table("notes")` with `reader.table(notesTable)`. Keep the rest of the query or write unchanged.

```ts confect/notes.impl.ts
import { GroupImpl } from "@confect/server";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";
import { FunctionImpl } from "./_generated/server";
import { DatabaseReader } from "./_generated/services";
import notesTable from "./_generated/tables/notes";
import notesGroup from "./notes.spec";

const list = FunctionImpl.make(notesGroup, "list", () =>
  Effect.gen(function* () {
    const reader = yield* DatabaseReader;
    return yield* reader.table(notesTable).index("by_creation_time").collect();
  }).pipe(Effect.orDie),
);

export default GroupImpl.make(notesGroup).pipe(
  Layer.provide(list),
  GroupImpl.finalize,
);
```

Use `Table.storageTable` and `Table.scheduledFunctionsTable` from [the server Table module](/server/database/system-tables) for system table reads. For a runtime choice between tables, [import only the relevant handles](/server/database/schema#selecting-a-table). Importing the full registry for convenience puts every application table back into the function's bundle.

## Keep names where no document codec is needed

Leave `Id("notes")`, `documentIds.parse("notes", input)`, and `vectorSearch("notes", index, query)` unchanged. `documentIds.identify(input)` still returns a table **name** paired with its ID. Native Convex APIs such as `ctx.db.query("notes")` also keep their string arguments.

## Update HTTP routes and tests

Pass just the routes layer to [`HttpRouter.make`](/server/http-api#creating-the-router). For [`TestConfect.layer`](/guides/testing#setup), pass the deployment schema and modules, and use the Confect schema as a type argument: `TestConfect.layer<typeof schema>(convexSchema, modules)`. Neither call takes the full Confect schema as a value.

## Replace plain-only implementation layers

Check each `.spec.ts`. If it declares one or more functions and **all** use `FunctionSpec.convex*`, keep its sibling `.impl.ts` but remove the default `GroupImpl` layer. Export the registered Convex functions under their declared names instead. If you already keep the functions in a separate module, re-export them:

```ts confect/workpool.impl.ts
export { backgroundWork, enqueue, onComplete, status } from "./workpool";
```

Alternatively, define them in the `.impl.ts` itself and use a type-only import from that file in the spec. The [plain Convex functions guide](/server/plain-convex-functions) shows the complete pair. Codegen selects direct exports from the declarations; no setting or file rename is required.

Keep the default finalized layer for groups that include any Effect function, even a single one alongside native functions. Empty groups keep their default finalized layer and expose no endpoint.

## Regenerate bindings

Upgrade the Confect packages and CLI together, run `confect codegen`, then typecheck your application. Do not hand-edit generated bindings.
