description: "Expose native Convex functions through typed Confect refs without adding a Confect runtime dependency to the handlers."
---

Some Convex libraries and [components](https://docs.convex.dev/components) expect you to define standard Convex functions in your project. For example, [Workpool](https://www.convex.dev/components/workpool), [Workflow](https://www.convex.dev/components/workflow), and [Migrations](https://www.convex.dev/components/migrations) all require user-defined Convex functions.

For a group whose spec declares only plain Convex functions, export the registered functions by name from `<group>.impl.ts`. Codegen re-exports those names directly: callers get typed Confect refs, but the Convex entry does not import Effect, the spec, or a Confect registration layer at runtime. A handler still loads its own dependencies.

The **spec** determines the shape of the impl, not the filename or the code inside it. A nonempty group of `FunctionSpec.convex*` declarations uses named exports. A group with any Effect function, including a [mixed group](#mixing-confect-and-plain-functions), uses a default finalized `GroupImpl` layer. Empty groups and specs that build subgroups inline also keep the layer form. Groups in separate files are classified independently.

## Spec constructors

| Constructor                             | Description                |
| --------------------------------------- | -------------------------- |
| `FunctionSpec.convexPublicQuery`        | Public query function      |
| `FunctionSpec.convexPublicMutation`     | Public mutation function   |
| `FunctionSpec.convexPublicAction`       | Public action function     |
| `FunctionSpec.convexPublicNodeAction`   | Public Node.js action      |
| `FunctionSpec.convexInternalQuery`      | Internal query function    |
| `FunctionSpec.convexInternalMutation`   | Internal mutation function |
| `FunctionSpec.convexInternalAction`     | Internal action function   |
| `FunctionSpec.convexInternalNodeAction` | Internal Node.js action    |

## Workpool component example

The [Workpool](https://www.convex.dev/components/workpool) component pools actions and mutations with configurable parallelism and retries. It requires you to define Convex functions that it can reference—such as the action to run and an `onComplete` callback. This walkthrough shows how to integrate those functions into Confect.

### Install the component

```bash
npm install @convex-dev/workpool
```

Register it in `convex/convex.config.ts`:

```ts convex/convex.config.ts
import { defineApp } from "convex/server";
import workpool from "@convex-dev/workpool/convex.config";

const app = defineApp();
app.use(workpool, { name: "workpool" });

export default app;
```

### Write the Convex functions

Write standard Convex functions in the group's `.impl.ts` file. Export each registered function under its name in the spec. The component reference comes from Confect's generated [components registry](/server/components#referencing-components).

```ts confect/workpool.impl.ts
import {
  type WorkId,
  Workpool,
  vWorkId,
  vOnCompleteArgs,
} from "@convex-dev/workpool";
import { v } from "convex/values";
import { internal } from "../convex/_generated/api";
import {
  internalAction,
  internalMutation,
  mutation,
  query,
} from "../convex/_generated/server";
import { components } from "./_generated/components";

const pool = new Workpool(components.workpool, {
  maxParallelism: 3,
});

export const enqueue = mutation({
  args: {},
  returns: vWorkId,
  handler: async (ctx): Promise<WorkId> => {
    return await pool.enqueueAction(
      ctx,
      internal.workpool.backgroundWork,
      {},
      { onComplete: internal.workpool.onComplete },
    );
  },
});

export const status = query({
  args: { workId: vWorkId },
  returns: v.union(
    v.object({
      state: v.literal("pending"),
      previousAttempts: v.number(),
    }),
    v.object({
      state: v.literal("running"),
      previousAttempts: v.number(),
    }),
    v.object({ state: v.literal("finished") }),
  ),
  handler: async (ctx, { workId }) => {
    return await pool.status(ctx, workId);
  },
});

export const backgroundWork = internalAction({
  args: {},
  returns: v.null(),
  handler: (): Promise<null> =>
    new Promise((resolve) => setTimeout(() => resolve(null), 3_000)),
});

export const onComplete = internalMutation({
  args: vOnCompleteArgs(),
  returns: v.null(),
  handler: async (_ctx, { result }): Promise<null> => {
    if (result.kind === "success") {
      console.log("Background work completed successfully");
    } else if (result.kind === "failed") {
      console.error("Background work failed:", result.error);
    }
    return null;
  },
});
```

### Define the spec

Use the `convex*` spec constructors and pass each native export's type as a type argument. Confect extracts argument and return types from the Convex registration so that refs are fully typed.

```ts confect/workpool.spec.ts
import { FunctionSpec, GroupSpec } from "@confect/core";
import type {
  backgroundWork,
  enqueue,
  onComplete,
  status,
} from "./workpool.impl";

export default GroupSpec.make()
  .addFunction(FunctionSpec.convexPublicMutation<typeof enqueue>()("enqueue"))
  .addFunction(FunctionSpec.convexPublicQuery<typeof status>()("status"))
  .addFunction(
    FunctionSpec.convexInternalAction<typeof backgroundWork>()(
      "backgroundWork",
    ),
  )
  .addFunction(
    FunctionSpec.convexInternalMutation<typeof onComplete>()("onComplete"),
  );
```

<Note>
  Import the Convex functions as **type-only** imports (`import type`). The spec
  is shared between the server and client, so a runtime import here would leak
  the function implementation to the client bundle.
</Note>

Run `confect codegen`. It checks that each declared export is registered with the right function kind and visibility. Typechecking the generated Convex module also checks arguments and return types. Only names declared in the spec become endpoints. These plain handlers do not run Confect middleware.

For native Node actions, use `GroupSpec.makeNode()` with the Node action spec constructors. For native queries and mutations, you can opt into [experimental context reuse](/server/functions#experimental-context-reuse); it does not change what the cold-start bundle imports.

### Call plain functions from the client

Plain Convex functions are available through refs just like Confect functions.

```tsx
import { useMutation, useQuery } from "@confect/react";
import refs from "../confect/_generated/refs";

const enqueue = useMutation(refs.public.workpool.enqueue);
const status = useQuery(refs.public.workpool.status, { workId });
```

## Mixing Confect and plain functions

A single group can contain both Confect functions (with Effect schemas) and plain Convex functions. Each function's spec constructor determines how it is registered and called.

```ts confect/notes.spec.ts
import { FunctionSpec, GroupSpec } from "@confect/core";
import * as Schema from "effect/Schema";
import notes from "./_generated/tables/notes";
import type { search } from "./search";

const list = FunctionSpec.publicQuery({
  name: "list",
  returns: () => Schema.Array(notes.Doc),
});

const searchSpec = FunctionSpec.convexPublicQuery<typeof search>()("search");

export default GroupSpec.make().addFunction(list).addFunction(searchSpec);
```

In the mixed group's `notes.impl.ts`, pass the Effect handler and the registered native function to the generated `FunctionImpl.make` builder as usual:

```ts
import { FunctionImpl } from "./_generated/server";
import notes from "./notes.spec";
import { search } from "./search";

const searchImpl = FunctionImpl.make(notes, "search", search);
```

Provide both function implementations to `GroupImpl.make(notes)`. Native functions in a mixed group keep their native semantics, but share the group's runtime bundle.
