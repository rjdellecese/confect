Convex caches query results, but when a query reads the current time, Convex [expires its cached result sooner](https://docs.convex.dev/production/best-practices/), even if its arguments and the data it reads haven't changed.

## What stays cached

Confect gives query handlers an Effect `Clock` whose unsafe accessors return constants: `0` for milliseconds and `0n` for nanoseconds. Effect uses those accessors internally, so logging with `Effect.log` or tracing with `Effect.withSpan` doesn't make a query time-dependent. This clock applies only to queries, not to mutations or actions.

## Opting in to real time

Confect leaves `Date.now()` unchanged. Calling it in a query reads real time and makes the result time-dependent. The same applies if a library you call uses `Date.now()` internally.

Effect's `Clock.currentTimeMillis`, `Clock.currentTimeNanos`, and `Clock.monotonicTimeNanos` also read real time. For example, this query reads the clock to return a `fetchedAt` timestamp:

```ts
import * as Clock from "effect/Clock";
import * as Effect from "effect/Effect";
import { DatabaseReader } from "./confect/_generated/services";
import notesTable from "./confect/_generated/tables/notes";

Effect.gen(function* () {
  const reader = yield* DatabaseReader;
  const rows = yield* reader
    .table(notesTable)
    .index("by_creation_time")
    .collect();
  const fetchedAt = yield* Clock.currentTimeMillis;

  return { fetchedAt, rows };
});
```

## Preferring cacheable alternatives

If you don't actually need sub-second accuracy inside the query, follow Convex's [recommended patterns](https://docs.convex.dev/production/best-practices/) to preserve caching:

- Pass a coarse timestamp (e.g. rounded to the minute or hour) as a query argument from the client.
- Maintain a boolean or status field on the document, updated by a scheduled function or mutation.
- Compute time-dependent values in a mutation or action and persist the result.
