Confect requires a small number of fixed entry-point files in your `confect/` directory (see [Project Structure](/concepts/project-structure)). Organize each group as a spec and a sibling implementation. The group's name is the file's path within `confect/` (its stem for top-level groups, the dot-joined directory path for nested groups).

## Spec and impl files

Use `.spec.ts` and `.impl.ts` suffixes for every group. The spec must default-export its `GroupSpec`; additional named exports (for example error classes) are fine. If the spec includes an Effect function or is empty, the impl default-exports a finalized `GroupImpl` layer. For a group containing only [plain Convex functions](#native-convex-functions), the impl uses named exports instead.

A complete pair looks like this. The impl default-imports its sibling spec, passes it to `FunctionImpl.make` and `GroupImpl.make`, and finalizes the resulting layer with `GroupImpl.finalize`:

```ts confect/notes.spec.ts
import { GroupSpec, FunctionSpec } from "@confect/core";
import * as Schema from "effect/Schema";

import notes from "./_generated/tables/notes";

const list = FunctionSpec.publicQuery({
  name: "list",
  returns: () => Schema.Array(notes.Doc),
});

export default GroupSpec.make().addFunction(list);
```

```ts confect/notes.impl.ts
import { GroupImpl } from "@confect/server";
import * as Effect from "effect/Effect";
import * as Layer from "effect/Layer";

import { FunctionImpl } from "./_generated/server";
import { DatabaseReader } from "./_generated/services";
import notesTable from "./_generated/tables/notes";
import notes from "./notes.spec";

const list = FunctionImpl.make(notes, "list", () =>
  Effect.gen(function* () {
    const reader = yield* DatabaseReader;

    return yield* reader
      .table(notesTable)
      .index("by_creation_time", "desc")
      .collect();
  }).pipe(Effect.orDie),
);

export default GroupImpl.make(notes).pipe(
  Layer.provide(list),
  GroupImpl.finalize,
);
```

Run `confect codegen` after adding or changing specs and impls.

<Note>
  A file's path within `confect/` determines the public Convex API path it
  produces—`confect/notes_and_random/notes.spec.ts` becomes
  `api.notes_and_random.notes.list` for the public query above. Renaming a file
  or directory renames the API path, so treat these paths as part of your API's
  contract.
</Note>

<Warning>
  Some test runners (such as Vitest and Jest) treat `.spec.ts` files as test
  files by default. If your test runner is picking up Confect spec files,
  configure it to exclude them. For example, in Vitest you can add
  `"**/*.spec.ts"` to the `test.exclude` array in your config.
</Warning>

## Native Convex functions

When a group declares only [native Convex functions](/server/plain-convex-functions), export the registered functions by name from the sibling `.impl.ts`. The spec can import their types without importing the handlers at runtime:

```
confect/
  workpool.impl.ts     ← named native Convex function exports
  workpool.spec.ts     ← spec (type-only imports from workpool.impl.ts)
```

## Middleware

[Middleware](/server/middleware) is declared and implemented as a `*.spec.ts`/`*.impl.ts` pair too, but it belongs to no single group, so it lives in the reserved `confect/middleware/` directory—one pair per middleware, each named after the middleware in PascalCase. Confect does not scan that directory for groups, so nothing is emitted into `convex/` for it.

```
confect/
  middleware/
    RequireUser.spec.ts   ← declaration: MiddlewareSpec.MiddlewareSpec (client-safe)
    RequireUser.impl.ts   ← implementation: MiddlewareImpl layer (server-only)
```

Each spec module default-exports its middleware and names the errors and services it provides as named exports; each middleware impl default-exports its layer.

## Node actions

[Node action](/server/node-actions) groups follow the same naming and export conventions as other groups. Use `GroupSpec.makeNode()` to select the runtime. Confect emits Convex's `"use node"` directive into the generated module based on the spec.

```
confect/
  email.spec.ts
  email.impl.ts
```

## Nested groups

When a group contains subgroups, place each subgroup's `.spec.ts`/`.impl.ts` pair inside a subdirectory named after the parent group. The parent group itself does not need a spec or impl file—it is composed from its subgroups by their paths.

```
confect/
  billing/
    invoices.spec.ts        ← group path billing.invoices
    invoices.impl.ts
    subscriptions.spec.ts   ← group path billing.subscriptions
    subscriptions.impl.ts
```
