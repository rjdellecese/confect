The `Auth` service provides access to the current user's identity. Unlike vanilla Convex (which returns `UserIdentity | null`), the Confect `Auth` service returns an `Effect` that fails with a typed error when no user is authenticated.

## Getting the user identity

```ts
import * as Effect from "effect/Effect";
import { Auth } from "./confect/_generated/services";

Effect.gen(function* () {
  const auth = yield* Auth;

  const identity = yield* auth.getUserIdentity;
});
```

`getUserIdentity` succeeds with the user's [`UserIdentity`](https://docs.convex.dev/api/interfaces/server.UserIdentity) or fails with `NoUserIdentityFoundError`.

To require an authenticated user across a whole group of functions—and provide the loaded user to every handler—use [middleware](/server/middleware) instead of repeating the lookup in each handler.

For authorization policies that differ only by allowed roles or a resource argument name, declare [middleware options](/server/middleware#parameterizing-a-policy) rather than creating a separate middleware for every variation. One role gate can accept `{ admin: true }` on one function and `{ editor: true, admin: true }` on another. If you [repeat a guard](/server/middleware#repeating-a-policy) on the same function, every attachment must pass.

## Handling unauthenticated requests

Use `Effect.catchTag` to handle the case where no user is logged in.

```ts
Effect.gen(function* () {
  const auth = yield* Auth;

  const identity = yield* auth.getUserIdentity.pipe(
    Effect.catchTag("NoUserIdentityFoundError", () => Effect.succeed(null)),
  );
});
```

## Configuration

Auth provider configuration goes in `confect/auth.ts`, which is passed through to Convex as-is. See the [Convex auth documentation](https://docs.convex.dev/auth) for setup details.

## Signing deployment JWTs

`MutationAuth.signJwt()` signs an ES256 JWT with your deployment's managed key. The service is available only in mutations and mutation-only middleware; `Auth` continues to provide identity lookup in every supported context.

```ts
import * as Effect from "effect/Effect";
import { Auth, MutationAuth } from "./confect/_generated/services";

const issueToken = Effect.gen(function* () {
  const auth = yield* Auth;
  const identity = yield* auth.getUserIdentity;
  const signer = yield* MutationAuth;

  return yield* signer.signJwt({
    claims: { sub: identity.subject, aud: "my-service" },
    expiresInSeconds: 60,
  });
});
```

The options use Convex's `SignJwtOptions` type. Convex enforces lifetime and reserved-claim rules; rejected signing operations become defects rather than typed errors.

Tokens are signed, not encrypted, and cannot be revoked individually. Use a short lifetime (at most one hour), authorize the caller before signing, and have the receiving service verify the signature, issuer, audience, and expiration against your deployment's `/.well-known/jwks.json` endpoint. See [Convex's signing API](https://docs.convex.dev/api/interfaces/server.MutationAuth).
