A Confect function can declare a typed error in its spec. When the handler fails with a value matching that schema, the error travels across the function boundary and surfaces—already decoded—at every call site (React hooks, JS clients, and tests).

Typed errors are transported as Convex's native [`ConvexError`](https://docs.convex.dev/functions/error-handling/application-errors#throwing-application-errors), with the encoded error stored in `ConvexError.data`. The `returns` channel is left untouched, and non-Confect callers of the same Convex API see ordinary `ConvexError`s. For mutations, throwing a `ConvexError` triggers Convex's transaction rollback as usual.

Error schemas are optional. When omitted, the error type defaults to `never` and every call site keeps its prior shape.

[Middleware](/server/middleware) can declare error schemas too; a middleware's errors join the error union of every function it covers, alongside the function's own `error` schema.

## Declaring an error schema

Add an `error` field to any `FunctionSpec` constructor. The schema is an ordinary Effect `Schema`, so a `Schema.TaggedError` class works well for a single failure mode.

```ts confect/notes.spec.ts
import { FunctionSpec, GroupSpec } from "@confect/core";
import * as Schema from "effect/Schema";

import { Id } from "./_generated/id";
import notes from "./_generated/tables/notes";

export class NoteNotFound extends Schema.TaggedError<NoteNotFound>()(
  "NoteNotFound",
  { noteId: Id("notes") },
) {}

export default GroupSpec.make().addFunction(
  FunctionSpec.publicQuery({
    name: "getOrFail",
    args: () => ({ noteId: Id("notes") }),
    returns: () => notes.Doc,
    error: () => NoteNotFound,
  }),
);
```

To declare more than one failure mode, combine them with `Schema.Union`.

```ts
import { FunctionSpec } from "@confect/core";
import * as Schema from "effect/Schema";

import { Id } from "./_generated/id";

export class NoteNotFound extends Schema.TaggedError<NoteNotFound>()(
  "NoteNotFound",
  { noteId: Id("notes") },
) {}

export class Forbidden extends Schema.TaggedError<Forbidden>()(
  "Forbidden",
  {},
) {}

FunctionSpec.publicMutation({
  name: "deleteOrFail",
  args: () => ({ noteId: Id("notes") }),
  returns: () => Schema.Null,
  error: () => Schema.Union([NoteNotFound, Forbidden]),
});
```

## Failing from a handler

When a spec declares an `error` schema, the corresponding `FunctionImpl` handler's `Effect` error channel is typed as that schema's `Type`. Use `Effect.fail` (or `Effect.mapError`) to fail with any value matching the schema.

```ts confect/notes.impl.ts
import * as Effect from "effect/Effect";

import { FunctionImpl } from "./_generated/server";
import { DatabaseReader } from "./_generated/services";
import notesTable from "./_generated/tables/notes";
import notes, { NoteNotFound } from "./notes.spec";

const getOrFail = FunctionImpl.make(notes, "getOrFail", ({ noteId }) =>
  Effect.gen(function* () {
    const reader = yield* DatabaseReader;

    return yield* reader
      .table(notesTable)
      .get(noteId)
      .pipe(Effect.mapError(() => new NoteNotFound({ noteId })));
  }),
);
```

Without an `error` schema, the handler's error channel is `never` and any unmapped failure must still be cleared (typically with `Effect.orDie`). With one, declared failures travel through, and any other failure (a defect) still rejects/dies as before.

## Consuming typed errors

The decoded error is surfaced at every call site. The exact shape depends on the client.

### `@confect/react`

- **`useQuery`** returns a `QueryResult<A, E>`. Match it with `QueryResult.match`, where `onFailure` is required when the ref declares an `error` schema.
- **`useMutation`** and **`useAction`** return `Promise<Result<A, E>>` when the ref declares an `error` schema (and `Promise<A>` otherwise). Handle the success and failure values with `Result.match` from `effect/Result`.

See [React](/clients/react) for full examples.

```tsx
import { QueryResult, useQuery } from "@confect/react";
import refs from "../confect/_generated/refs";

const lookup = useQuery(refs.public.notes.getOrFail, { noteId });

QueryResult.match(lookup, {
  onLoading: (skipped) => (skipped ? null : "Looking up…"),
  onSuccess: (note) => `Found: ${note.text}`,
  onFailure: (error) => `Note ${error.noteId} not found.`,
});
```

### `@confect/js`

Both `HttpClient` and `WebSocketClient` add the decoded error to the returned `Effect`'s error channel, alongside the client's transport error and `Schema.SchemaError` from `effect/Schema` (for argument encoding or return-value decoding failures).

The imports from `@confect/js` are module namespaces, not client instances. Acquire the service inside `Effect.gen`, then call its methods with your generated refs:

```ts
import { HttpClient } from "@confect/js";
import * as Effect from "effect/Effect";

import type { Id } from "../confect/_generated/id";
import refs from "../confect/_generated/refs";

const lookup = (noteId: Id<"notes">) =>
  Effect.gen(function* () {
    const client = yield* HttpClient.HttpClient;

    return yield* client.query(refs.public.notes.getOrFail, { noteId });
  });
```

The Effect returned by `lookup` requires `HttpClient.HttpClient`; provide `HttpClient.layer(deploymentUrl)` when running it, as shown in [HTTP](/clients/js/http).

The WebSocket service's `reactiveQuery` method carries typed errors too. When the subscribed query fails, its `Stream` terminates with the decoded value in the error channel:

```ts
import { WebSocketClient } from "@confect/js";
import * as Effect from "effect/Effect";
import * as Stream from "effect/Stream";

import type { Id } from "../confect/_generated/id";
import refs from "../confect/_generated/refs";

const watchNote = (noteId: Id<"notes">) =>
  Stream.unwrap(
    Effect.gen(function* () {
      const client = yield* WebSocketClient.WebSocketClient;

      return client.reactiveQuery(refs.public.notes.getOrFail, { noteId });
    }),
  );
```

Provide `WebSocketClient.layer(deploymentUrl)` to the Effect that consumes this stream. To handle query failures without ending the subscription, call the acquired client's `reactiveQueryResult` instead. It emits successes and failures as `Result` values while leaving the Convex subscription open, so later updates can recover. Argument-encoding failure happens before subscription: it emits one failed `Result` and ends without opening a listener. See [WebSocket](/clients/js/websocket) for consumption and recovery examples.

### `@confect/test`

`TestConfect`'s `query`, `mutation`, and `action` decode typed errors into the `Effect` error channel, so test bridges see the same shape as the JS clients. See [Testing](/guides/testing).

## Non-typed failures

Backend failures that do not match a declared `error` schema are not silently swallowed. In `@confect/react`, mutation and action promises reject, while query hooks throw during render to the nearest React error boundary. In `@confect/js`, these failures become `HttpClientError` or `WebSocketClientError`: ordinary calls fail their `Effect`, `reactiveQuery` fails its stream, and `reactiveQueryResult` emits a failed `Result`. In `TestConfect`, undeclared backend failures surface as defects in the cause. Use a typed `error` schema for domain failures you want callers to handle by type.
