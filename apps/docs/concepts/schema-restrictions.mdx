Not every Effect schema is valid for use in Confect. In Effect v4, `Schema.Codec<Type, Encoded, DecodingServices, EncodingServices>` tracks both representations of a value and the services required to convert between them. `Schema.Schema<Type>` tracks only the decoded type; it does not preserve the encoded type or service requirements.

For schemas used in Confect:

- `Type` is the decoded value you work with in your code. It does not have to be a Convex value.
- `Encoded` is the value stored in the database or sent as a Convex function argument or result. It must be a valid [Convex value](https://docs.convex.dev/database/types#convex-values).
- `DecodingServices` lists the Effect services required to decode `Encoded` into `Type`.
- `EncodingServices` lists the Effect services required to encode `Type` into `Encoded`.

Confect's table and function schemas must have `never` for **both** service requirements. Effect defaults both parameters to `never`, so `Schema.Codec<Type, Encoded>` expresses a codec with no decoding or encoding service requirements. Providing services to a function handler does not remove this restriction on its schemas.

For example, `Schema.DateFromString` decodes a string into a JavaScript `Date` and encodes a `Date` back into a string, without requiring services:

```typescript
import * as Effect from "effect/Effect";
import * as Schema from "effect/Schema";

const dateCodec: Schema.Codec<Date, string> = Schema.DateFromString;

const roundTrip = Effect.gen(function* () {
  const date = yield* Schema.decodeEffect(dateCodec)(
    "2026-01-01T00:00:00.000Z",
  );
  const encoded = yield* Schema.encodeEffect(dateCodec)(date);
  return { date, encoded };
});

const result = await Effect.runPromise(roundTrip);
```

Here, `result.date` is a `Date` and `result.encoded` is `"2026-01-01T00:00:00.000Z"`. The encoded string is a Convex value even though the decoded `Date` is not.

Confect decodes documents when reading from the database and encodes them when writing. For function calls, Confect callers encode arguments and decode results; the server decodes arguments before the handler runs and encodes the handler's result before returning it.

## Function argument fields

Convex functions always receive an object, so Confect function specs declare `args` as a `Schema.Struct` field map rather than as an arbitrary schema:

```typescript
FunctionSpec.publicQuery({
  name: "byAuthor",
  args: () => ({ author: Schema.String }),
  returns: () => Schema.Array(Schema.String),
});
```

Confect lazily wraps that field map in `Schema.Struct`. A full schema such as `args: () => Schema.String` or `args: () => Schema.Struct(...)` is therefore not accepted. Top-level struct checks and annotations cannot be attached directly to function args; if you need a cross-field check, nest the checked struct under an argument field.

For a function with no arguments, omit `args`; Confect defaults it to an empty field map (`{}`).

## Additional caveats

### Optional-property safety

Confect requires `strict: true` in your TypeScript configuration.
`exactOptionalPropertyTypes: true` is optional but recommended. See
[Effect Schema's explanation of `exactOptionalPropertyTypes`](https://effect.website/docs/v4/schema/introduction#the-exactoptionalpropertytypes-option)
for how it affects optional properties and schema validation.

### No-op returns from Convex functions

Unlike the vanilla APIs, Convex functions defined with Confect may not return `undefined` or `void`—use `null` (`Schema.Null` as the `returns` validator) instead. Convex coerces `undefined`/`void` returns to `null` anyways—this just makes that more explicit.

```typescript ✅
FunctionSpec.publicQuery({
  name: "myQuery",
  returns: () => Schema.Null,
});
```

```typescript ❌
FunctionSpec.publicQuery({
  name: "myQuery",
  returns: () => Schema.Undefined,
});
```

```typescript ❌
FunctionSpec.publicQuery({
  name: "myQuery",
  returns: () => Schema.Void,
});
```
